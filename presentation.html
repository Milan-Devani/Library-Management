BACKGROUND

Problem Statement & Motivation

Manual Paper Registers

Physical paper logs suffer from misplaced records, torn pages, handwriting ambiguity, and lack of searchability.

Stock Inaccuracy

Difficulty in maintaining real-time physical inventory counts versus books currently issued to students.

Manual Fine Calculation

Librarians waste time manually counting overdue days and computing penalty fees, leading to errors and audit disputes.

Zero Student Self-Visibility

Borrowers have no immediate way to view active loans, impending due dates, or check catalog book availability.

SYSTEM DESIGN

3-Tier System Architecture

Tier 1: Client Presentation Layer (React 18 + Vite)

Runs directly inside the browser. Manages client-side protected routing, Redux Toolkit slices, reusable UI components, and input validation.

Tier 2: Business Logic & REST Gateway (Pure PHP 8.2)

API gateway inspects incoming requests, verifies Bearer tokens, executes circulation domain logic, and enforces institutional borrowing limits.

Tier 3: Relational Database Layer (MySQL / MariaDB)

Guarantees ACID transactions, pessimistic row-level locking (SELECT ... FOR UPDATE), foreign key constraints, and port auto-fallback.

CONCURRENCY & SAFETY

ACID Transactions: Issue vs. Return

Issue Transaction Flow

BEGIN TRANSACTION;
1. Lock member & verify status == 'active'
2. Check student active loans < 3
3. Check no duplicate active loan
4. Lock book row & check available > 0
5. INSERT INTO issues (...)
6. UPDATE books SET available = available - 1
COMMIT;

Return Transaction Flow

BEGIN TRANSACTION;
1. Lock issue & verify status == 'issued'
2. Calculate overdue days = max(0, Return - Due)
3. Calculate fine = overdue_days * fine_rate
4. UPDATE issues SET status = 'returned'
5. UPDATE books SET available = available + 1
6. If fine > 0: INSERT INTO fines (...)
COMMIT;

BUSINESS RULES

Automated Fine Calculation Engine

Server-Enforced Fine Formula

Overdue Days = MAX( 0, Return Date − Due Date )
Fine Amount = Overdue Days × ₹5.00 / day

DEVELOPMENT JOURNEY

Engineering Challenges Faced

Challenge 1

Dual Port Conflicts (3306 vs 3307)

Developer computers often run both MySQL 8 and XAMPP MariaDB, causing connection refused errors.

Challenge 2

Concurrency & Stock Overselling

Risk of two librarians issuing the last copy at the same second causing negative inventory counts.

Challenge 3

Zero Page-Reload Synchronization

Keeping counts, badges, and tables in sync without forcing disruptive browser reloads.

Challenge 4

Responsive Table Layouts

Large data tables (ISBN, Title, Student, Status) overflowing small mobile viewports.

Library Management System Slide 17 / 21
TECHNICAL INNOVATION

Technical Solutions Implemented

PDO Port Auto-Fallback Connector

Smart database singleton automatically tests port 3306 and seamlessly switches to 3307 if refused, guaranteeing zero setup configuration hassle.

Pessimistic Row Locking

Implemented SELECT ... FOR UPDATE within atomic MySQL transactions, locking stock rows during loans to prevent overselling.

Redux AsyncThunk Architecture

7 domain slices with extraReducers handling pending, fulfilled, and rejected promise lifecycles with optimistic state mutation.

Responsive Card & Table Layouts

Mobile-first Tailwind grid layouts with horizontal overflow wrappers and collapsible navigation for all screen sizes.
